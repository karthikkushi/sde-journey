## What it is

How software engineer hiring at Google usually works, so the long-term goal feels concrete.
The usual entry level for engineers is **L3** (Software Engineer II); **L4** is a mid-level engineer, **L5** a senior one. Hiring decisions are made from written interview feedback, not by a single interviewer, and the process changes over time, so confirm details with your recruiter and the official "How we hire" page on Google's careers site.

## Real-life example

Like a competitive exam with an interview board: several separate rounds, each examiner writes notes, and a separate committee reads all the notes before a decision. One bad round does not always end it, but you need strong signals across the rounds.

## Picture

```text
 apply (referral helps get a look) ─▶ recruiter call ─▶ technical screen (1–2 coding interviews, ~45 min)
      ─▶ interview loop (about 4–5 rounds):
            coding / algorithms × 3–4    ◀ data structures, patterns, clean code, testing, Big O
            Googleyness & leadership × 1  ◀ behavioural (STAR stories)
            (system design: usually for L4+)
      ─▶ written feedback ─▶ hiring committee ─▶ team matching ─▶ offer
```

## How it works inside

- **Coding rounds**: medium to hard problems, often in a simple editor without running the code or autocomplete. Graded on problem solving, coding quality, communication, and testing your own code.
- **Behavioural round**: collaboration, handling ambiguity, ownership, helping others, doing the right thing. Prepare STAR stories.
- **Level**: decided from your experience and interview performance. Down-levelling (offered L3 when you applied for L4) happens; level affects pay and expectations.
- **Hiring committee**: reviews all the feedback together for consistency.
- **Team matching**: after a positive decision you talk with teams that have openings; this can take weeks.
- **Timeline**: from first call to offer often takes one to a few months.
- **If rejected**: you can usually apply again after some months; ask the recruiter. Many engineers got in on a later attempt.
- **What this plan builds towards**: ~300 problems with patterns, timed practice, thinking aloud, STAR stories, a real project, and mock interviews.

## Time and space

| Round | Length | Focus |
| --- | --- | --- |
| Technical screen | ~45 min | 1–2 coding problems |
| Coding (loop) | ~45 min each | algorithms + clean code + testing |
| Googleyness & leadership | ~45 min | behavioural stories |
| Hiring committee + team match | weeks | no action from you except team calls |

## Common mistakes

- Preparing only by grinding problems, with no talking aloud or mock interviews.
- Relying on autocomplete and running code; practise in a plain editor.
- Ignoring the behavioural round.
- Applying without a referral when you could ask someone you know.
- Treating one rejection as final.
